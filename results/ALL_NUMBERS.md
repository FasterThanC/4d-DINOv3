# All numbers of the project (reference for writing the report)

Generated by `scripts/make_numbers_reference.py` from the raw per-run result files that the UCloud
jobs wrote (not typed by hand). The per-run files are collected in `exp2_runs.json`,
`exp1_time/exp1_runs.json` and `robustness_pair1_code/pair1_code_runs.json`. Checked three ways (see the last section). Test set = PASTIS fold 5.

## 0. How to read the numbers

- **mIoU** = mean over the 19 classes 0–18 (background + 18 crops) of IoU, in %; class 19 (void) is
  ignored. Same formula as U-TAE. **OA** = overall pixel accuracy (void ignored).
- **mean ± std**: std is over seeds, population std (`np.std`, ddof = 0) in every table of this
  project (our code and Pair 1's code). With ddof = 1 it would be about 1.22× larger.
- **95% CI**: paired bootstrap over the 496 test series (1000 resamples, seed 0). Seeds are pooled by
  summing their confusion matrices, so the CI point ("pooled") can differ by ±0.05 from the
  difference of the seed means. Use the CI line when you give a CI, the table means otherwise.
- Rounding: tables to 1 decimal, differences to 2 decimals (or 1 in text).
- Two meanings of "shuffled dates" — keep them apart in the text:
  1. **trained with shuffled dates** (Tables 1 and 2): each image gets another image's date in
     training and test. Measures how much the correct dates are worth.
  2. **shuffled only at test time** (Table 3, "reliance"): a model trained with real dates is tested
     with shuffled dates. Measures how much a trained model depends on the dates.
- **Never mix rows of different tables** except the DINOv3 row, which is the same runs in Tables 1–3.

## 2. Models and training settings

| item | value |
|---|---|
| teacher | DINOv3 ViT-L/16, SAT-493M weights (`facebook/dinov3-vitl16-pretrain-sat493m`), frozen, 303.1 M parameters |
| student backbone | DINOv3 ViT-S/16 (LVD-1689M start weights), first layer replaced by a 10-band layer (RGB weights copied into B4/B3/B2, other bands start at 0), input z-scored per band (PASTIS normalisation, folds 1–3), 22.3 M parameters |
| student training | images of folds 1–3 (68,786), no labels; 20 epochs (537 steps each), batch 128, AdamW lr 2e-4 for the backbone and 1e-3 for the heads, wd 0.05, 1 warm-up epoch then cosine decay; checks on 4,000 fold-4 images |
| copy loss | mean over tokens of 1 − cosine similarity between the student token after a linear layer (384 → 1024) and the DINOv3 token |
| rebuild loss | MSE of the 7 non-RGB bands (B5, B6, B7, B8, B8A, B11, B12; z-scored) of the 8 × 8 pixels under each token, predicted from the token by a 2-layer MLP (384 → 384 → 7 × 64) |
| student 1 / 2 / 3 | copy only (λ = 0) / copy + rebuild (λ = 1) / rebuild only (copy weight 0); students 1 and 2 trained 3 times (seeds 0, 1, 2), student 3 once |
| temporal model (all our tables) | L-TAE (d_model 256, 16 heads, d_k 4, MLP 256 → 128; GroupNorm computed over real dates only, padded dates ignored) + decoder of 4 conv blocks with three ×2 bilinear upsamplings (16 → 128 px) and a 1 × 1 conv to 19 classes |
| L-TAE training (Tables 1–3) | 15,000 steps, batch 8 series, AdamW lr 1e-3, wd 1e-4, 5% warm-up then cosine decay, cross-entropy (void ignored); up to 32 random dates per series in training (redrawn each time), all dates at val/test; best fold-4 checkpoint (checked every 500 steps) tested on fold 5; seeds 0, 1, 2 |
| mean baseline | average of the image features over the dates (in training: over the same random ≤ 32 dates), then 1 × 1 conv + BatchNorm + ReLU to 128 channels and the same decoder; no time input |
| one-date baseline | least cloudy image whose date is in the calendar month (Sep/Oct: 2018 and 2019 images both count); if a series has none, the image closest to the 15th of the month; mean-pool decoder on that one image |
| cloud-free dates | images with ≤ 20% cloudy pixels; if fewer than 8 remain, the 8 least cloudy are kept |
| time encodings | none = no time input; position = order k of the image among the used dates, encoded as 10·k; date = days since 2018-09-01; both = half the encoding dims for position, half for date; same sinusoidal encoder as the official L-TAE |
| benchmark | NVIDIA B200, batch 64, 256 × 256 input: teacher 1643 img/s, student 7760 img/s |
| Pair 1's code (robustness only) | official L-TAE + their decoder, lr 3e-3, 80 epochs, batch 16, wd 1e-2, all dates in training, same cloud rule, same padding fix |

## 9. Claims the numbers support (and ones they do not)

Supported:
1. Many dates beat one date: mean of all dates +6.7, L-TAE +22.1 mIoU over the best single month.
2. The L-TAE learns to ignore cloudy images (attention 0.04 vs 1.23); removing clouds by hand helps the mean (+0.86) but not the L-TAE (-0.28, CI includes 0).
3. Most of the L-TAE's gain does not need any time input: L-TAE without time is +12.8 over the mean of cloud-free dates.
4. Correct dates add a small but clear amount: real vs shuffled +1.76 [1.24, 2.27]; order +1.20, calendar date +0.56 more. Training with shuffled dates equals no time input (49.8 vs 49.8).
5. Trained with real dates, DINOv3 + L-TAE does depend on them at test (drop 12.0), but far less than U-TAE
   trained on raw bands (drop 48.3).
6. Copying DINOv3 into a 13.6× smaller, 4.7× faster 10-band student keeps its accuracy (S1 − DINOv3 +0.38 [-0.12, +0.91], not significant).
7. Adding the rebuild loss gives +2.40 mIoU [1.98, 2.87] over copy only, in each of 3 student trainings, also with 10% labels, and raises NDVI R² from 0.89 to 0.94.
8. That gain is not from using the dates more: gap S2 − gap S1 = -0.04 [-0.52, +0.47] (100%).
9. Copying DINOv3 is not needed for the gain: student 3 (rebuild only) ≈ student 2 (-0.56 [-1.20, +0.18], one training).

Not supported / be careful:
- Do not say students use timing more than DINOv3 in general: gap S2 − gap DINOv3 is +0.80 [+0.24, +1.38] at
  100% labels but not at 10% (+0.12 [-0.39, +0.62]); with test-time shuffling S2 drops 2.0 more than DINOv3.
  Mixed evidence → describe, don't claim.
- Student 3's large test-time drop (26.7) comes from one student training; its tokens are far from DINOv3.
- Student vs DINOv3 mixes two changes (10 bands and ViT-S vs ViT-L); S2 vs S1 is the clean comparison.
- One test fold (fold 5), not 5-fold cross-validation. Std over 3 seeds is small but seeds are few.
- Tokens cover 80 m × 80 m; small fields are mixed with their neighbours.
- Cloud detection = blue threshold only (no cloud shadows; bright soil or snow may count as cloud).
